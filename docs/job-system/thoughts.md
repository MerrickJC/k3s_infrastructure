# Brainstorm
I am designing a system. The system contains thousands of files, each around 10GB in size. These files are all indexed using a range of different algorithms. Some algorithms, for example, will compute averages of values stored within the files, while other algorithms may calculate the total variation of a value stored within the files. The algorithms themself aren't super important, but there are multiple different indexing computations that each file must go through during ingestion. Each algorithm will produce exactly one output, which is stored in a jsonb field in a postgres database. Each algorithm can be written as its own python function that accepts that file as an input and computes the value as an output, as well as the name of the variable being used for the output when stored in postgres. Indexing these files requires copying the file to a worker server, running a script and producing an output. I am currently leaning towards storing each Python function as its own script. This means if a new script is added, all the files need to be downloaded and only need to run that one script. On the downside, when a new file is added, it must have multiple scripts run against it which (to be efficient) requires more complex orchestration of jobs sequentially (to reduce re-downloading files)
