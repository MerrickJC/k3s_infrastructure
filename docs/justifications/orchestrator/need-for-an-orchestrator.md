# Need For An Orchestrator Justification
One of the key goals of creating this platform is to support the re-simulation of ROS bags. The desired approach for achieving this is to utilise a containerised docker image containing a ROS node and run this code while a ROS bag is re-played. Since ROS nodes require running in the native OS environment (see https://doi.org/10.48550/arXiv.1704.02696) a container provides the most reproducible and scalable way to achieve this. To facilitate operating at scale, a container orchestration tool was required. Kubernetes is the industry standard container orchestration tool (see https://doi.org/10.1145/3539606) which lends itself to being applied to this situation. Kubernetes provides further benefits, such as reducing cloud vendor lock-in, simplifying aggregation of multiple servers, and providing a wide range of existing tools and frameworks.
